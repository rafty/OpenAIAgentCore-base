# Pull Request Message作成Skill

## 目的

現在の要件ブランチ全体をレビューできるように、`main` との差分に基づくPull Requestタイトルと本文を作成する。

## 入力

主な入力は次のとおりである。

- 現在のGitブランチ
- base branch。指定がない場合は `main`
- base branchと現在のブランチとの差分全体
- 現在のブランチに含まれるコミット履歴
- 差分に含まれるSDD成果物、ADR、README、`docs/`
- 確認できるテスト・検証結果
- 会話中に明示された関連Issue、レビュー観点、対象外、後続課題

## 出力

`assets/pull-request-template.md` の形式に従い、次を出力する。

1. Pull Requestタイトル
2. Pull Request本文

## 最初に確認すること

次の順序で確認する。

1. リポジトリのルートと適用される `AGENTS.md`
2. 現在のブランチとbase branch
3. 作業ツリーに未コミットの変更があるか
4. base branchから現在のブランチまでのコミット履歴
5. base branchと現在のブランチとの差分一覧、差分量、具体的な差分
6. 変更されたfeature directoryとSDD成果物
7. 変更されたADR、README、`docs/`
8. 確認できるテスト・検証結果

確認に使用する代表的なコマンド。base branchが異なる場合は `main` を置き換える。

```bash
git branch --show-current
git status --short
git log origin/main..HEAD --oneline
git diff --name-status origin/main...HEAD
git diff --stat origin/main...HEAD
git diff origin/main...HEAD
```

`origin/main` が最新か確認できない場合は、その制約を明記する。明示的な許可なしにネットワーク操作を行う必要はない。

## 作業手順

1. 現在のブランチが `main` ではないことを確認する。
2. base branchと現在のブランチの比較範囲を確定する。
3. コミット履歴と差分から、ブランチ全体の目的を一つに整理する。
4. 変更されたfeature directoryとSDD成果物を特定する。
5. 実装、設定、テスト、文書、ADRなどの変更内容を分類する。
6. `tasks.md` のタスクIDが差分または会話から確認できる場合は整理する。
7. 実行済みと確認できるテスト・検証だけを整理する。
8. 未実施の検証が明示されている場合は、理由とともに整理する。
9. 差分から判断できるレビュー観点を整理する。
10. `spec.md` や会話で対象外が明示されている場合は整理する。
11. Pull Requestタイトルを作成する。
12. テンプレートに従ってPull Request本文を作成する。
13. 出力前に、タイトルと本文がブランチ全体の差分と一致することを確認する。

## Pull Requestタイトルのルール

- 要件ブランチ全体で実現した内容を一行で表す。
- 原則としてConventional Commits形式を使用する。
- 日本語で簡潔に記載する。
- 個々のコミットの列挙ではなく、要件として何を実現したかを書く。
- 末尾に句点を付けない。
- ブランチが一つのコミットだけの場合でも、タイトルはブランチ全体の目的から作成する。

例:

```text
feat(cdk): AgentCore GatewayをAWS CDKで構築
```

## Pull Request本文のルール

本文には、確認できる範囲で次を記載する。

- 背景・目的
- 変更内容
- SDD成果物
- 対応タスク
- 検証結果
- レビュー観点
- 対象外
- 関連情報
- 未確定事項、未解決事項、後続課題

空の項目や該当しない項目は、意味のないプレースホルダーを残さず削除する。ただし、検証を実施していない場合は、項目自体を削除せず未実施であることを明記する。

## 作業ルール

- Pull Requestメッセージは、ステージ済み差分だけではなく、base branchと現在のブランチとの差分全体を説明する。
- コミットメッセージを連結しただけの本文にしない。
- 差分に含まれない変更を記載しない。
- 未コミットの変更がある場合は、その変更がPull Request差分に含まれないことを報告する。
- 実行していないテストや検証を、成功または完了として記載しない。
- `tasks.md` のチェック状態だけを根拠に、検証結果を推測しない。
- 関連Issue、タスクID、ADR、対象外が確認できない場合は推測しない。
- SDD成果物を必須入力として決め打ちしないが、差分に含まれる場合はPull Request本文に記載する。
- タイトルと本文は日本語で作成する。
- 明示的に依頼されない限り、`git push`、Pull Request作成、マージを実行しない。
- base branchとの差分を変更する操作は行わない。

## 出力ルール

- Pull Requestタイトルと本文を分け、コピーして使用できる形式で出力する。
- タイトルは一つの推奨案を出力する。
- 本文には、差分と確認済み情報に基づく具体的な内容を記載する。
- 情報が不足する項目は、推測で埋めず「未確認」または「未実施」と明記する。
- 複数の独立した要件が一つのブランチに混在している場合は、メッセージを無理にまとめず、Pull Request分割が必要であることを報告する。

## 自己レビュー

出力前に次を確認する。

- タイトルがブランチ全体の目的を表しているか。
- 本文がbase branchと現在のブランチとの差分全体を説明しているか。
- コミットメッセージの単純な再掲になっていないか。
- 変更内容とSDD成果物の記載が実際の差分と一致しているか。
- テスト・検証結果が確認済みの事実だけで構成されているか。
- レビュー観点が具体的か。
- 対象外や未解決事項を推測していないか。
- 未コミットの変更がある場合に、その制約を見落としていないか。
- 一つのPull Requestに複数の独立した要件が混在していないか。
